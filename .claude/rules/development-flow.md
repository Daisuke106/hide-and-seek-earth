# 開発フロー

## ブランチ戦略

GitHub Flow を採用する。

```
main
└── feature/xxx   # 機能開発
└── fix/xxx       # バグ修正
└── docs/xxx      # ドキュメント更新
└── chore/xxx     # 雑務（依存更新など）
```

## 開発の流れ

1. `main` から作業ブランチを切る
2. 実装・テストを行う
3. プルリクエストを作成する
4. コードレビューを受ける
5. レビュー承認後に `main` へマージする
6. 作業ブランチを削除する

## プルリクエストのルール

- 1PRの変更は小さく保つ（レビューしやすいサイズにする）
- PRタイトルは変更内容が一目でわかるように書く
- レビュアーを必ず1名以上アサインする
- CIが通過していることを確認してからレビュー依頼する
- `main` への直接pushは禁止

## コードレビューの観点

- 機能要件を満たしているか
- セキュリティ上の問題がないか
- パフォーマンス上の問題がないか
- テストが十分か
- コーディング規約に従っているか
